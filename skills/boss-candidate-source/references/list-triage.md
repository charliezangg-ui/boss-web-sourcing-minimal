# 两级候选人分流

## 一级：决定是否打开

在用户确认的筛选条件下实际读取卡片工作经历、职责线索、学历/年限、期望薪酬和已确认排除项。年龄、性别、照片不参与判断。期望/最近关注金额不是当前薪资；低于某金额只按用户定义的岗位信号处理，不自动硬淘汰。公司与关键词也不证明本人责任。

在打开详情前冻结一条证据理由与三类结论：`open_first`（具体相关项目/整体责任线索）、`uncertain`（卡片不足以判定）、`skip_visible_mismatch`（可见事实已明确冲突）。优先打开第一类；若仍需扩充，读取 uncertain；明确跳过只记录事实和对应规则，不做平台淘汰。一级只控制读取顺序，不能直接推荐、开聊或给未校准概率分。

## 二级：决定是否联系

打开并完整覆盖详情，按[逐关判断](../../boss-candidate-screen/references/decision-gates.md)区分可联系、明确不符、证据不足和读取失败。管理头衔或品牌不自动通过；局部模块执行与整体持续负责有别。首次联系与面试推进门槛分开。一级原始预测、二级结论、后续人工反馈各自保存，不能回改原判断。

## 抽查与计量

正式任务到用户终点即停；用户授权策略评估时可预先冻结从跳过者中抽查的样本、范围和随机种子，另记详情成本，不用已停止任务暗中扩展。记录真正读过的唯一卡片、一级三类、详情、合格、抽查与漏选；DOM已加载但未检查不计。记录开始、首位合格、完成时间；没有同口径对照不宣称节省时间或 token。抽查前不能声称漏选率为0。

会话入口也遵守逐人闭环：先列表检查点，再一级分流，必要详情，判定与动作落盘后才看下一人。一级明确不合适的新招呼只完成已读。
