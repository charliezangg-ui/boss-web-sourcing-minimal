# 会话状态与处理

顶部分类可有新招呼、沟通中、我发起、已获取简历、收藏、已交换微信/电话等；这些是入口，不等于业务结果。一个会话对应一个候选人，列表缩略卡片与完整在线简历分层读取，顶部岗位筛选器必须核对。实际按钮与分类每次以当前页面为准。

| 状态 | 证据 | 后续 |
|---|---|---|
| new_unread | 目标岗位新未读入站 | 打开前保存列表检查点，读全文 |
| outbound_only | 我方末条，无候选人入站 | 等待，不自动催促 |
| no_action_unfit | 主动来聊且明确不合适 | 已读、落盘，不发拒绝 |
| insufficient_evidence | 材料可读但缺少必要证据 | 保留缺口，不当明确不匹配 |
| blocked_read | 详情未完整读或身份歧义 | 保存断点，不伪作不合适 |
| fit_interested | 资格及入站意向明确 | 回复并按授权求完整简历 |
| resume_text_verified | 标准话术发送回读 | 核对按钮步骤 |
| resume_button_verified | 求简历按钮提交回读 | 等待真实附件 |
| waiting_resume | 已请求但未收到完整附件 | 有新入站再处理，不重复请求 |
| resume_received | 同人完整附件或在线简历可见 | 按授权下载及核验 |
| refused | 明确拒绝/停止 | 结束跟进 |
| needs_user_decision | 薪资承诺、面试、内部信息等 | 在当前任务升级，不代答 |

打开会话可能使未读变已读；已登记的 intent/unknown 事务必须按同人同岗精确恢复。新发现只用未读，不能扫历史已读补量。平台“已获取简历”分类与真实附件逐一核验，不能以分类名称替代文件存在。收藏、微信、电话不等于收到简历。
