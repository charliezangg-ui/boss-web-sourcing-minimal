# 竞招名额与付费窗口

竞招名额、占用方式和费用以当前账号页面为准，不沿用其他账号的历史上限，也不把“开放中”总数直接当竞招占用数。出现付费窗口先保存提示、关闭窗口、回岗位列表核对新岗位名称、JD、薪资和状态；只有已保存且未在招的证据才记 `created_unpublished_verified`。未知保存结果先只读核验，不重新建岗。

若还有其他已授权岗位，继续逐岗创建；名额限制只阻塞受影响岗位的开放。登录、安全验证、控制权变化另走共享契约。需要替换时列出拟关闭旧岗与拟开放新岗，让用户明确两个具体对象；笼统“可以”若无法唯一定位对象，不能自行选择。确认后复用已保存新岗，按页面要求关闭旧岗并回读名额，再开放新岗并回读。关闭成功不等于开放成功。用户不同意或未回复时保留现状与未发布新岗；部分成功/状态未知分别报告，未知写入不重放。

验收分别覆盖：名额窗口后岗位保存、具体替换的关闭与开放各自回读、拒绝替换时原在招状态保持。规则推演不等于网页实测。
