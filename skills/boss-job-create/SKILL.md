# 岗位绑定与创建

输入：用户目标、当前账号、JD及版本、城市和授权动作。寻访前读开放中的岗位及完整JD，核对名称、城市、主体和状态；同名或近似标题不足以绑定。现有列表用“开放中”判断在招，用“全部”检查重复；已关闭岗位只列出，不自动复制或恢复。

创建岗位时先做批次字段计划：title、JD、类型、经验、学历、薪资上下限与月数、地点、工作性质、各值来源（用户/JD/推断）和偏差。用户没有给定的值不可冒充明确要求；影响发布或筛选的缺口一次性请用户决定。读取当前表单实际选项，可用[岗位类型目录](references/boss-job-types.md)作为历史线索，但必须现场核对，不硬编码历史分类。类型改变后重读关键词与相关字段。

基于当前页面分阶段填写，提交前核对全部字段及公司/账号。用户授权创建并提交时可提交保存；用户仅要草稿则停在草稿，网页无草稿能力则仅保留私有本地草稿。提交前保存 intent；提交后逐岗回读 `draft_saved/submitted/open/under_review/unknown`，不能把提交当在招。若弹出付费名额限制，记录、关闭窗口、回读是否已保存未发布的岗位，再继续其他已授权岗位。关闭或替换旧岗、购买名额另行确认具体对象与费用；详见[竞招名额](references/paid-capacity.md)。每岗结果立即落盘，失败或 unknown 不重放。

岗位特定招呼语按[话术配置](references/job-greeting.md)设置并读回；[中性模板](templates/job-greeting.txt)只作为草稿，不自动写入账号；账户通用预设也要核对，因为点击“打招呼”可能立即发送。创建和配置招呼语是两步，不能以岗位保存证明话术已生效。
