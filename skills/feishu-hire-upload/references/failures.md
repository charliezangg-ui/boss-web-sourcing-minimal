# 上传失败索引

| 症状 | 处理 | 结束条件 |
|---|---|---|
| 配置缺失、CLI 或 Node 不可用 | 按返回的 onboarding 及[接入配置](setup.md)主动引导，补齐当前缺项 | 配置与环境检查通过 |
| 已有配置损坏或不可读 | 按 repair_config 修复原文件，保留状态库和断点 | 配置可读且未覆盖原状态 |
| profile、岗位或来源不匹配 | 核对同一应用的 discover 结果；切换组织用独立状态库 | 原授权目标和实际映射一致 |
| 缺少应用权限 / 数据不可见 | 展示缺失 scope 和后台入口，按[接入配置](setup.md)引导开通、数据范围及发布审批；不对 bot 使用个人登录代替 | 对应接口可读；写权限仍按真实业务验证 |
| 缺少租户必填字段 | 核对租户设置并补真实字段 | 字段满足要求，重新准备受影响计划 |
| 身份不明、多个匹配或多份同岗投递 | 留 needs_review，核对真实身份与既有投递 | 唯一映射有依据；不全量扫描或猜测合并 |
| 已上传同文件 | 复用本地及远端回执 | 不重复创建人才、投递或附件 |
| 计划不匹配或过期 | 核对原输入与计划；无 unknown 时重新 prepare | 使用覆盖当前动作的有效计划 |
| 外部写入结果未知 | 停写并 reconcile；保留原文件、计划与 checkpoint | 原计划所有目标回读完成，否则 unknown |
| 找不到人才 checkpoint | 用原任务证据查询远端人才和正式附件，不盲重试 | 身份与既有写入明确后再恢复 |
| 状态库被锁定 | 核对持有进程；确认进程结束并保留未知写入后清理遗留锁 | 同一状态库只有一个执行者 |

部分步骤成功不等于整条任务成功；不能把应创建投递的任务降级为“仅人才入库”来结案。
