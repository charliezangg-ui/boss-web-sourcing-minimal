# 推荐牛人筛选器实测目录

历史页面观察：以下为曾见控件，使用时必须核验当前账号和页面；不是本项目的默认筛选值。

| 字段 | 实测选项 |
|---|---|
| 年龄 | 范围滑块，当前16至不限；未枚举全部刻度 |
| 院校 | 不限、985、211、双一流院校、留学、国内外名校、公办本科 |
| 活跃度[单选] | 不限、刚刚活跃、今日活跃、3日内活跃、本周活跃、本月活跃 |
| 近期没有看过 | 不限、近14天没有 |
| 是否与同事交换简历 | 不限、近一个月没有 |
| 性别 | 不限、男、女 |
| 专业 | 不限、电力电气类、电子信息类、机械类、计算机类、自动化类 |
| 牛人关键词 | JAVA、HTML、SPRING、CSS、PYTHON、VUE、MYSQL、前端开发、GIT |
| 跳槽频率[单选] | 不限、5年少于3份、平均每份工作大于1年 |
| 学历要求 | 不限、初中及以下、中专/中技、高中、大专、本科、硕士、博士 |
| 经验要求 | 不限、在校/应届、26年毕业、27年毕业、27年后毕业、1年以内、1-3年、3-5年、5-10年、10年以上 |
| 求职状态 | 不限、离职-随时到岗、在职-暂不考虑、在职-考虑机会、在职-月内到岗 |
| 薪资待遇[单选] | 不限、3K以下、3-5K、5-10K、10-20K、20-50K、50K以上 |

专业与关键词为动态选项；其他字段为固定字段集，固定的是选项结构，不是所有岗位使用同一值。经验中的毕业年份可能随年份更新，不能永久硬编码。

## 保存与复用

- 筛选面板底部“确定”提交本轮选择，未确认直接关闭会丢弃临时选择；不要把临时active当生效。
- “清除”后仍需“确定”。回读入口“筛选·N”及重开面板的active项。计数只作辅助，不能代替逐字段回读。
- 实测选择活跃度3日内并确定，重开保留；叠加近14天没有并确定，重开保留；从精选切推荐保留二者；清除并确定后二者恢复不限。三个case通过。未测试跨登录会话或所有跨岗位继承方式。
- “是否应用上次的筛选条件？”提供取消/应用，不等于可命名多预设；仅在上次条件与本岗位计划完全一致时应用，再核对。未发现命名预设入口。
- 专业“修改筛选专业”曾有搜索及14大类，可选最多5个、仅当前职位。修改候选项与实际勾选筛选项是两层操作；专业弹窗确定后仍核验主筛选面板并提交。历史专业保存尚未实测。
- 关键词历史页面为候选标签点击选择，未见任意自由文本输入。不要假设关键词支持AND/OR、布尔表达式或自定义；按当前岗位选项映射，并记录无法表达的语义。
- 本地按job_ref+surface+version存窄/宽预设JSON；应用时由当前DOM逐字段映射并确定，保存effective值。不要上传或注入未公开API。
- 城市在筛选面板外单独设置，含“仅推荐期望城市为本城市的牛人”；其按钮是“确认”，与筛选面板“确定”不同，不混用隐藏的城市按钮。
- 年龄、性别维持不限，不作为招聘筛选；跳槽频率未被用户确认为岗位条件时不设；院校、学历及其宽窄阶段只按当前用户和岗位条件执行。院校和学历标签不替代项目证据。

如用户本轮明确要求“只看第一学历”，选择后提交并重开核验。历史组合测试未覆盖该项和全部薪资/经验档位，不构成当前页面完整验收。

历史实测：推荐页整页reload后已保存筛选曾变为全部不限。刷新后必须重新应用本运行已确认预设并逐项回读（含第一学历）；不能重新询问已确认条件，也不能把清空条件的列表计入原预设实验。切推荐/最新的持久性与整页刷新分别记录。
