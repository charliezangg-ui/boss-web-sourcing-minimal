# 跨模块编排与恢复

## 目标与状态

用户授权的岗位、数量、筛选条件和截止点构成一个 run。一次工具调用、页面、模型回合或自然日不是新 run，也不是完成条件。每岗计算 `remaining = original_target - verified_qualified_unique_sends`；换页、放宽可选召回条件、暂停及恢复后重新按同人发送证据计算，不能按点击次数累计或归零。只有 `target_reached` 或用户明确终点才能 completed；暂停留原 run_id、下一动作、筛选版本、页面、未决写入及剩余量。运行终止后的质量修订不自动补量。

每次执行片段结束前核对（可使用可选的 `scripts/check-run.mjs` 读取私有 state.json；它只检查计数状态，候选人级发送证据仍须按运营日志核验）：`target_reached`（全部目标有证据）、`continue_same_run`（有可执行剩余工作）、`wait_external`（登录/验证/控制权/付费或未知写入等真实阻塞）、`unknown`（计数或状态缺证）。`continue_same_run` 在当前回合可继续时直接继续。宿主强制结束时只保存断点并如实告知；只有独立执行器已实际接管同一 run 才能称为自动续接。不可将进度报告、用户确认、低通过率或下一阶段开始时间当成提前完成。

## 串行与阻塞范围

同一浏览器空间的 UI 写入串行。账号登录/安全验证/身份歧义停止 BOSS 操作；付费或单岗未开放只阻塞受影响动作，独立授权工作可继续。写入结果 unknown 冻结同一事务及依赖步骤，先查原会话或文件，不能重放。读取故障可按失败模块有界恢复；同类故障复现时暂停该读取流程，不批量跳过候选人。

## 候选人事务

新消息只用未读发现；已登记未完成事务按同人同岗精确恢复，不受已读状态阻断。候选人主动沟通：明确不适合者仅完成已读并记事实；合适者回复实际问题，再按[标准话术与求简历按钮](../../boss-conversation/SKILL.md)获取完整简历。已发起沟通：未回复不催；有新回复时核对身份、指纹、既有请求与附件，再逐步处理。请求成功、承诺发送、收到附件和下载核验为不同状态。单轮扫描冻结截止时间或队列，后到消息留下一轮，避免无限滚动饿死寻访。

## 记录与汇报

每个对象完成后即时更新运行账本；切策略前先保存完整实际条件与原因。日志或回读失败暂停新增外部写入，已验证动作不撤销也不重放。报告区分成功、失败、未知、待回复及数据覆盖，不能将本地报告、平台徽标或发送 intent 当作完成证据。当前包不自带后台调度或外部消息桥接。
