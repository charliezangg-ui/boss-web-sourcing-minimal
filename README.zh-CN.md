# BOSS 网页招聘模块化 Skills

**语言：**[English](README.md) · [简体中文](README.zh-CN.md)

这是一组用于 BOSS 直聘招聘端网页的 Codex Skills。[总入口](skills/boss-sourcing/SKILL.md)按任务定位四条常用 workflow，并复用 15 个 Skill 入口与模块：岗位创建、筛选器、寻访、完整简历读取、匹配评审、打招呼、收藏、会话处理、候选人跟进、收简历、招聘数据、运营日志、失败恢复、安全验证反馈，以及总入口。索引负责定位，workflow 负责组合，业务模块和失败索引维护具体规则。推荐招呼、用户描述或JD创建岗位、推荐收藏、会话处理分别有直接入口；详细策略和规则仍保留在对应模块中。

## 运行条件

- Codex 环境需要能控制已登录 BOSS 招聘端网页的浏览器工具。桌面应用的内置浏览器需 Computer Use 可用并启用；CLI/IDE 环境需另配浏览器控制工具。参见 [OpenAI 浏览器说明](https://learn.chatgpt.com/docs/browser?surface=app)。Ego Lite 等独立任务空间可减少与用户手动浏览的干扰，但不是必需依赖；实际 token 效果取决于工具与页面。
- 招聘账号需能访问目标岗位、JD、候选人和会话。用户需给出或确认准确岗位、授权动作、目标及硬性条件。登录和安全验证由人完成。
- 需要私有可写位置存放可续接的运行记录及已授权下载的简历。本项目不提供凭据、飞书/ATS 接入、调度服务或特定公司的招聘画像。
- 完整简历读取包含可选的 Ego Lite/macOS 适配脚本。要运行它们，另需本机具备 `ego-browser` CLI、Node.js、Python 3 与 macOS Swift/Vision；只使用浏览器工具手动完成同等读取流程则无需这些脚本。脚本不是跨浏览器通用驱动。

安装时将 `skills/` 下各目录放到 Codex 能发现 Skill 的位置，并保持模块、引用和脚本的相对目录结构。组合任务调用 `boss-sourcing`；单项任务可调用对应模块。正式运行前应检查浏览器工具是否能操作当前页面、账号预设招呼语是否准确。离线校验不能证明当前网站全部控件可用。

示例：“用 boss-sourcing 处理我的在招后端岗位。JD 如下：[…]。筛选候选人，最多给 5 位符合岗位的人打招呼，处理新回复，并向有意向的人索取完整简历。保存私有运行记录。”

## 长任务中断时的兜底

Codex 执行较长的招聘任务时可能在达到目标前中断。对于长期或无人值守任务，建议用户将 Codex 接入办公 IM，并按自行设定的周期汇报进度。每次汇报应基于已保存的运行记录，列出原目标、已核验完成数、剩余量、最近断点，以及 `blocked` 或 `unknown` 动作。

遇到 BOSS 登录或安全验证、浏览器控制权丢失、写入结果无法核验，或其他无法安全解决的问题，应及时向用户预警：暂停受影响动作，保存断点，并说明恢复前需要用户处理的事项。IM 收件人、汇报频率、送达核验和自动续接调度均需另行配置与授权；本项目不自带 IM 桥接或后台执行器。

## 范围与安全

这些 Skills 不预置薪资、年限、院校、来源排除或特定岗位画像。一级卡片仅决定读取优先级，联系候选人需有简历详情证据。外发消息、创建岗位需要用户授权。发送和收件均需同人回读；写入未知先只读核验，不重放未知动作。不绕过平台安全验证、不擅自消耗付费权益、不公开候选人数据、不自动上传到飞书招聘。

本项目仅供个人研究与学习，不用于商业用途；与 BOSS 直聘无关联。使用者应自行核查平台规则、适用法律、权限和候选人资料处理要求。用途声明本身不保证相关操作被允许，本项目不提供法律意见。

## 新岗位规则

Agent根据JD和用户提供的规则自动生成完整岗位JSON；尚未决定的明确可比较选项默认采用最严格方案，保留已确认决定与例外。新岗位的薪资与年限仍需用户确认，规则齐全且执行已获授权后才开始。模板不预置任何公司的招聘门槛。参见[生成与确认规则](skills/boss-candidate-screen/references/role-rule-generation.md)。
